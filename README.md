# نظام الامتحانات الإلكترونية — مادة اللغة الإنجليزية

موقع ثابت (Static Web App) بالكامل — HTML + CSS + JavaScript — بدون أي خادم
Node.js وبدون PHP وبدون MySQL. كل ما يحتاج "Backend" (تسجيل دخول، قاعدة
بيانات، صلاحيات) ينفَّذه Firebase (Authentication + Firestore + Security
Rules). صالح للرفع مباشرة على GitHub Pages.

## 2) إعداد Firebase خطوة بخطوة

1. اذهب إلى https://console.firebase.google.com واضغط **Add project** وأنشئ
   مشروعًا جديدًا (يمكن تعطيل Google Analytics، غير ضروري لهذا المشروع).
2. من داخل المشروع: **Build > Authentication > Get started**.
   - فعّل مزوّد **Email/Password** (لدخول الأستاذ).
   - فعّل مزوّد **Anonymous** (لدخول الطلاب بدون كلمة مرور).
3. من **Build > Firestore Database > Create database**، اختر وضع **Production
   mode** (سنكتب قواعد الأمان يدويًا بأنفسنا في الخطوة التالية).
4. من **Project settings (⚙) > General > Your apps**، اضغط أيقونة **</>** لإضافة
   تطبيق ويب (Web app)، وسمِّه مثلًا "exam-system". لا تحتاج Firebase
   Hosting — سنستخدم GitHub Pages.
5. انسخ كائن `firebaseConfig` الذي يظهر لك، وضعه داخل `js/firebase-config.js`
   مكان القيم النائبة (`ضع-...-هنا`).
6. **إنشاء حساب الأستاذ** (لا توجد صفحة تسجيل عامة عمدًا، لحماية النظام):
   - من **Authentication > Users > Add user**، أضف بريد الأستاذ وكلمة مرور.
   - انسخ **User UID** الذي يظهر بجانب المستخدم الجديد.
   - من **Firestore Database > Start collection**، أنشئ Collection باسم
     `teachers`، ثم أنشئ مستندًا (Document) معرّفه (Document ID) هو نفس الـ
     UID الذي نسخته، وأضف له الحقول:
     - `name` (string): اسم الأستاذ الظاهر في اللوحة
     - `email` (string): نفس البريد المستخدم في Authentication
   - هذه الخطوة اليدوية هي ما يمنع أي شخص من "تسجيل نفسه" كأستاذ عبر الموقع.
7. **رفع قواعد الأمان**: من **Firestore Database > Rules**، الصق محتوى ملف
   `firestore.rules` كاملًا واضغط **Publish**.
8. **الفهارس المركّبة**: بعض الاستعلامات (مثل ترتيب الأسئلة داخل امتحان) تحتاج
   فهرسًا مركّبًا. إما:
   - انسخ محتوى `firestore.indexes.json` وأنشئ الفهارس يدويًا من تبويب
     **Firestore Database > Indexes**، أو
   - شغّل الموقع مباشرة؛ إذا ظهر خطأ "The query requires an index" في
     Console المتصفح (F12)، ستجد رابطًا جاهزًا داخل رسالة الخطأ ينشئ الفهرس
     المطلوب بضغطة واحدة. كرّر ذلك حتى تختفي الأخطاء (عادة 3 فهارس فقط).

## 3) تشغيل المشروع محليًا

المشروع Static بالكامل، فلا حاجة لأي بناء (build). يكفي تشغيل خادم ملفات
بسيط من داخل مجلد المشروع، مثال:

```bash
# باستخدام Python (متوفر غالبًا افتراضيًا)
python3 -m http.server 8080

# أو باستخدام حزمة npx (تحتاج Node.js مثبتًا على جهازك للتطوير فقط،
# وليس كخادم مطلوب أثناء التشغيل الفعلي للموقع)
npx serve .
```

ثم افتح `http://localhost:8080` في المتصفح. **ملاحظة:** فتح ملفات `file://`
مباشرة بدون خادم محلي قد يمنع Firebase من العمل بشكل صحيح في بعض المتصفحات؛
استخدم دائمًا خادمًا محليًا ولو بسيطًا.

## 4) الرفع إلى GitHub ثم تفعيل GitHub Pages

```bash
cd exam-system
git init
git add .
git commit -m "Initial commit: exam system"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```

ثم من صفحة المستودع على GitHub:
1. **Settings > Pages**.
2. من **Source** اختر **Deploy from a branch**.
3. اختر Branch: `main` والمجلد `/ (root)`، ثم **Save**.
4. بعد دقيقة أو دقيقتين سيظهر رابط مثل:
   `https://USERNAME.github.io/REPO_NAME/`

افتح الرابط وستجد `index.html` يعمل مباشرة.

> **تنبيه هام حول Firebase Authentication ونطاقات الدخول المصرّح بها:**
> من **Authentication > Settings > Authorized domains** في Firebase Console،
> أضف نطاق GitHub Pages الخاص بك (مثل `USERNAME.github.io`) حتى يعمل تسجيل
> الدخول من الموقع بعد رفعه (localhost مضاف افتراضيًا للتطوير المحلي).

## 5) طريقة دخول الأستاذ

- افتح `teacher-login.html`، أدخل البريد وكلمة المرور اللذين أنشأتهما في
  الخطوة (6) من قسم إعداد Firebase.
- بعد الدخول تُنقل تلقائيًا إلى `teacher-dashboard.html`.
- من **إعدادات الحساب** في الشريط الجانبي يمكنك تغيير اسم العرض أو كلمة
  المرور (يتطلب تغيير كلمة المرور إدخال كلمة المرور الحالية أولًا لأسباب
  أمنية، وهذا ما يفرضه Firebase Authentication).

## 6) طريقة إنشاء امتحان

1. من لوحة التحكم اضغط **+ امتحان جديد**.
2. عبّئ اسم الامتحان، الوصف، رمز الامتحان (Exam Code فريد)، الحالة، تاريخ
   ووقت البداية والنهاية، ومدة الامتحان بالدقائق، ثم اضغط **حفظ بيانات
   الامتحان**.
3. بعد الحفظ الأول سيظهر قسم **أسئلة الامتحان** أسفل الصفحة. اضغط **+ إضافة
   سؤال**، اختر النوع (اختيار من متعدد / صح وخطأ / إجابة قصيرة / مقالي)،
   واملأ التفاصيل والدرجة والإجابة الصحيحة، ثم **حفظ السؤال**.
4. يمكنك تعديل ترتيب الأسئلة بالأسهم، أو تعديلها أو حذفها في أي وقت.
5. لا تنسَ تغيير حالة الامتحان إلى **منشور** عندما يصبح جاهزًا لدخول الطلاب.

## 7) طريقة دخول الطالب

1. الطالب يفتح `student-login.html`، يكتب اسمه الرباعي ورمز الامتحان،
   ويضغط **دخول الامتحان**.
2. يتحقق النظام تلقائيًا من: وجود الامتحان، أنه منشور، أن الوقت الحالي داخل
   فترة الامتحان، وأنه لا يملك محاولة سابقة مكتملة.
3. عند القبول، يُنقل لصفحة `exam.html` حيث يبدأ العداد التنازلي تلقائيًا.
4. يمكنه تحديث الصفحة أو إغلاقها والعودة، وستُستأنف محاولته طالما لم ينتهِ
   الوقت ولم يسلّم الامتحان بعد. لا يمكنه إطلاقًا إنشاء محاولة ثانية.

## 8) طريقة مشاهدة النتائج

1. من لوحة التحكم اضغط زر **النتائج** بجانب أي امتحان.
2. اضغط **تصحيح تلقائي للأسئلة الموضوعية** لتصحيح Multiple Choice وTrue/False
   وShort Answer دفعة واحدة لجميع الطلاب.
3. اضغط على اسم أي طالب لعرض تفاصيل إجاباته سؤالًا سؤالًا، مع الإجابة
   الصحيحة (تظهر للأستاذ فقط)، ودرجة كل سؤال.
4. للأسئلة المقالية، أدخل الدرجة يدويًا واضغط **حفظ الدرجة**؛ بعد تصحيح كل
   الأسئلة المقالية (إن وجدت) تتحول حالة الطالب تلقائيًا إلى **تم التصحيح**
   وتظهر له درجته النهائية إذا فتح `student-result.html?exam=EXAM_ID`.

## 9) بنية قاعدة البيانات (Firestore)

| Collection    | معرّف المستند (Document ID)         | أهم الحقول |
|---------------|--------------------------------------|------------|
| `teachers`    | Firebase Auth UID                    | name, email |
| `students`    | Firebase Auth UID (مجهول)            | fullName, lastSeenAt |
| `exams`       | تلقائي                               | title, description, examCode, status, startAt, endAt, durationMinutes, questionCount, teacherId, allowShowAnswers |
| `questions`   | تلقائي (مشترك مع answerKeys)         | examId, type, text, options{a,b,c,d}, points, order — **بدون أي إجابة صحيحة** |
| `answerKeys`  | نفس معرّف السؤال في `questions`      | examId, correctAnswer أو acceptableAnswers[] — **يُقرأ من الأستاذ فقط** |
| `attempts`    | `${examId}_${studentUid}`            | examId, studentUid, studentName, status, startedAt, submittedAt, violationCount, totalScore, maxScore |
| `answers`     | `${attemptId}_${questionId}`         | attemptId, examId, questionId, studentUid, answerValue, autoScore, teacherScore |
| `violations`  | تلقائي                               | attemptId, examId, studentUid, type, timestamp |

**سرّ فصل `questions` عن `answerKeys`:** Firestore Security Rules تعمل على
مستوى المستند بأكمله وليس على مستوى الحقل الواحد؛ فلا يمكن "السماح بقراءة
السؤال لكن منع قراءة حقل الإجابة الصحيحة داخل نفس المستند". الحل العملي
الوحيد بدون خادم (Cloud Functions) هو فصل الإجابة الصحيحة في مستند/Collection
منفصلة تمامًا، تُمنع قراءتها كليًا عن الطالب (راجع `firestore.rules`).

## 10) كيف يتم التصحيح التلقائي بدون خادم (Cloud Functions)؟

بما أن المشروع مطلوب أن يعمل بدون Node.js كخادم، ولا Cloud Functions، فإن
عملية التصحيح التلقائي (المقارنة بين إجابة الطالب والإجابة الصحيحة) تُنفَّذ
داخل **متصفح الأستاذ نفسه** عند فتحه لصفحة النتائج والضغط على "تصحيح
تلقائي". هذا آمن تمامًا لأن الأستاذ هو المستخدم الوحيد المصرَّح له أصلًا
بقراءة `answerKeys` حسب قواعد الأمان — فلا يحدث أي تسريب للإجابات الصحيحة
لأي طرف آخر. **الحد الوحيد لهذا التصميم:** إذا أراد الأستاذ تصحيحًا فوريًا
تلقائيًا بمجرد تسليم كل طالب (بدون فتح صفحة النتائج بنفسه)، فهذا يتطلب
منطقًا يعمل من جهة الخادم (Cloud Functions)، وهو خارج النطاق المسموح به في
هذا المشروع. البديل المطبَّق هنا هو الأفضل الممكن ضمن القيود المطلوبة.

## 11) حدود معروفة (بصراحة تامة، دون ادّعاء حماية مطلقة)

- **الاسم الرباعي ليس هوية آمنة:** أي طالب يمكنه كتابة اسم طالب آخر. النظام
  يعتمد فعليًا على هوية Firebase (uid) لمنع محاولة ثانية، وليس على الاسم.
  النظام يعرض تحذيرًا توعويًا إذا وجد اسمًا مطابقًا مسبقًا، لكنه لا يستطيع
  التأكد يقينًا من هوية الشخص الحقيقي خلف الشاشة.
- **مسح بيانات المتصفح أو تغيير الجهاز** يمنح الطالب هوية Firebase (uid)
  جديدة، وبالتالي قد يتمكن نظريًا من محاولة جديدة. هذا حدّ متأصل في أي نظام
  لا يفرض كلمة مرور شخصية لكل طالب — وقد طُلب صراحة عدم إلزام الطلاب بحساب
  وكلمة مرور.
- **لا يمكن لأي كود JavaScript منع المستخدم فعليًا** من فتح تبويب جديد أو
  الخروج من المتصفح أو استخدام جهاز آخر للغش. المتصفح لا يمنح صفحات الويب
  العادية سيطرة كاملة على جهاز المستخدم. ما تم تنفيذه هو أفضل نظام مراقبة
  ممكن ضمن حدود المتصفح (رصد فقدان التركيز، تبديل التبويب، النسخ/اللصق...).
- **حدث `beforeunload`** قد لا يكتمل إرسال طلب تسجيل المخالفة قبل إغلاق
  الصفحة فعليًا — هذا حدّ معروف في منصّات الويب.
- **الوقت المعروض للطالب (Countdown) يعتمد على ساعة الطالب** لغرض العرض
  فقط بعد أن كان "لحظة الانطلاق" مأخوذة من ساعة خادم Firebase
  (`serverTimestamp`)، لذلك لا يستطيع الطالب "تمديد" وقته بتغيير ساعة
  جهازه — لكن لضمان قطع صارم عند اللحظة صفر بدقة الميلي ثانية حتى لو أغلق
  المتصفح، يتطلب ذلك مهمة مجدولة من جهة الخادم (Cloud Scheduler / Cloud
  Functions)، وهو خارج نطاق "موقع ثابت بدون خادم". كحل عملي: عندما يعود
  الطالب لصفحة الامتحان بعد انتهاء وقته، يتم تسليم محاولته تلقائيًا فورًا.

## 12) ملاحظة أمنية حول Firebase API Key

مفتاح `apiKey` في `js/firebase-config.js` **ليس كلمة سر سرّية**؛ هو مصمَّم
من Google ليكون ظاهرًا داخل كود الواجهة الأمامية لأي تطبيق ويب يستخدم
Firebase. الحماية الحقيقية للبيانات تأتي حصرًا من:
- **Firebase Authentication** (لإثبات هوية المستخدم بشكل موثوق).
- **Firebase Security Rules** (لتحديد من يملك صلاحية قراءة/كتابة كل مستند).

لذلك لا داعي لمحاولة "إخفاء" apiKey، لكن يجب الحرص الشديد على صحة وصرامة
ملف `firestore.rules`.

## 14) الأمان: مراجعة نقطة بنقطة

| التهديد | الحماية المطبَّقة |
|---|---|
| XSS | لا استخدام لـ `innerHTML` لعرض نص خارجي دون تمريره عبر `escapeHtml()` أولًا |
| قراءة الإجابات الصحيحة | `answerKeys` منفصلة تمامًا ولا تُرسل أبدًا لمتصفح الطالب، وقواعد الأمان تمنع قراءتها لغير الأستاذ صاحب الامتحان |
| إنشاء محاولة ثانية | معرّف المحاولة حتمي (`examId_uid`) + قواعد أمان تمنع الكتابة فوق محاولة موجودة أو تعديل حقولها الجوهرية |
| تعديل الدرجة من الطالب | حقول `autoScore` و`teacherScore` ممنوعة صراحة من كتابة الطالب في قواعد الأمان |
| تغيير وقت الامتحان | `startedAt` غير قابل للتعديل بعد إنشائه (تفرضه قواعد الأمان)، والمهلة تُحسب منه لا من ساعة الجهاز |
| الوصول للوحة الأستاذ | `guardTeacherPage()` + رفض أي قراءة/كتابة فعلية من قواعد الأمان حتى لو تجاوز الطالب واجهة المستخدم |
| تعديل البيانات من Developer Tools | كل كتابة تمر عبر Firestore وتُقيَّم مقابل `firestore.rules` بغض النظر عمّا يُرسله المتصفح |
| تجاوز الصلاحيات عبر استدعاء Firebase مباشرة | لا فائدة له: القواعد نفسها تُطبَّق على أي طلب مهما كان مصدره |

## 15) قائمة الاختبارات المطلوب تجربتها يدويًا

1. تسجيل دخول الأستاذ ببريد وكلمة مرور صحيحين.
2. إنشاء امتحان جديد وحفظ بياناته.
3. إضافة الأنواع الأربعة من الأسئلة للامتحان.
4. نشر الامتحان (تغيير الحالة إلى "منشور").
5. دخول طالب بالاسم الرباعي ورمز الامتحان الصحيح.
6. محاولة دخول امتحان بحالة "مسودة" → يجب أن يُرفض.
7. محاولة دخول امتحان بعد انتهاء `endAt` → يجب أن يُرفض.
8. محاولة دخول نفس الامتحان مرتين بنفس المتصفح → يجب أن يُرفض في المرة الثانية.
9. الإجابة على جميع الأسئلة والتأكد من ظهور مؤشر الحفظ دون أخطاء.
10. الانتظار حتى انتهاء الوقت والتأكد من التسليم التلقائي.
11. الضغط على "تسليم الامتحان" يدويًا قبل انتهاء الوقت.
12. من صفحة النتائج: الضغط على "تصحيح تلقائي" والتأكد من ظهور درجات
    الأسئلة الموضوعية فورًا.
13. تصحيح سؤال مقالي يدويًا والتأكد من تحديث الدرجة الكلية والحالة.
14. فتح تفاصيل إجابات طالب معيّن والتأكد من ظهور الإجابة الصحيحة للأستاذ فقط.
15. أثناء الامتحان: تبديل التبويب أو تصغير النافذة، والتأكد من ظهور تحذير
    وتسجيل مخالفة تظهر لاحقًا في عدّاد المخالفات عند الأستاذ.
16. تحديث صفحة الامتحان أثناء تنفيذه، والتأكد من استمرار نفس المحاولة
    وبقاء الإجابات المحفوظة سابقًا.
17. إغلاق المتصفح تمامًا أثناء الامتحان والعودة لاحقًا (قبل انتهاء الوقت)
